Approved, with the following corrections before implementation.

1. Primary muscle coefficient

The primary specific muscle must always use coefficient 1.0.

The trainer may edit coefficients only for secondary muscles.

Secondary coefficients may use values from 0.0 to 1.0, with suggested common values:

- 0.25 — minor meaningful contribution
- 0.5 — significant secondary contribution
- 0.75 — very strong secondary contribution

Do not present these values as scientifically exact.

2. Do not count stabilising muscles automatically

The system should track muscles receiving a meaningful training stimulus, not every muscle involved in stabilisation.

Correct the bench press example to:

- Mięsień piersiowy większy — primary — 1.0
- Mięsień trójgłowy ramienia — secondary — 0.5
- Przednia część mięśnia naramiennego — secondary — 0.5

Do not include serratus anterior by default.

3. Backward compatibility

Existing exercises may temporarily have zero specific-muscle assignments.

Do not force a destructive backfill during the migration.

However:

- when specific-muscle metadata is saved for an exercise, exactly one primary muscle is required;
- every newly created exercise should require exactly one primary specific muscle once the new form is active.

4. Database integrity

Keep the unique constraint preventing the same muscle from being assigned twice to one exercise.

Also enforce that an exercise cannot have more than one primary muscle at database level, preferably with a partial unique index or the safest equivalent supported by the current database.

Do not rely only on frontend or API validation.

5. Atomic updates

Creating or updating all muscle assignments for an exercise must happen inside one database transaction.

If validation fails, no partial muscle assignments should be saved.

6. Broad category consistency

The specific muscle broadCategory must use exactly the same allowed category vocabulary as exercises.mainMuscleGroup.

Do not create a second inconsistent set of category names.

7. Scope

Now implement only:

- specific muscle catalogue
- exercise-to-muscle assignments
- database migration
- API validation
- trainer exercise form and details UI

Do not implement:

- weekly volume calculations
- workout plan editor
- AI analysis
- client-facing display

Keep all existing exercise library functions working.

After implementation:

- run type checking and available tests
- verify existing exercises still load
- verify duplicate muscles are rejected
- verify two primary muscles are rejected
- verify coefficients outside 0–1 are rejected
- verify failed updates do not partially save data

============================================================
6. DISTRIBUTION ALGORITHM
============================================================

Input for every target:

- targetId
- targetName
- selectedWeeklyVolume from Phase 2
- sessionMin
- sessionMax
- eligible days based on split
- priority order if present

Distribute volume using units of 0.5.

Requirements:

1. Sum of all daily allocations for a target must exactly equal selectedWeeklyVolume.
2. Prefer the most even distribution across eligible days.
3. Use deterministic tie-breaking by day index.
4. Priority targets may receive earlier-day placement when the distribution is uneven.
5. Never change the selected weekly volume.
6. Never allocate to an ineligible day unless there are no eligible days.
7. If no eligible day exists:
   - distribute across all days,
   - return TARGET_WITHOUT_ELIGIBLE_DAY.
8. Respect sessionMax for the target where mathematically possible.
9. When weekly volume cannot fit under sessionMax across available eligible days:
   - distribute as evenly as possible,
   - do not reduce weekly volume,
   - return TARGET_SESSION_MAX_EXCEEDED.
10. sessionMin is informational only in Phase 3A:
   - return TARGET_SESSION_BELOW_MIN when a positive allocation is below sessionMin,
   - do not artificially increase the allocation.

Use a largest-remainder or equivalent deterministic algorithm operating in 0.5 units.

Avoid floating-point sum errors.

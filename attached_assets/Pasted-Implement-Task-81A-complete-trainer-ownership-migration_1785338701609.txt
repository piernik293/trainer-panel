## Current confirmed problems

- The initial trainer has now signed in.

- The authenticated client list is empty because it filters by trainer_id.
- The dashboard still displays old recent clients, creating inconsistent ownership behavior.

## Goal

After this task:

- all existing clients are safely assigned to the initial trainer,
- every newly created client always has a trainer owner,
- each trainer generates a unique one-time survey invitation,
- submitting that invitation creates a client belonging only to that trainer,
- the dashboard and client list use the same ownership rules,
- inaccessible clients show a proper error instead of an infinite loading state,
- the application administrator can access all clients,
- ordinary trainers can access only their own clients.

## 1. Verify initial trainer state

Before changing data, verify:

- exactly one trainer row exists,

Abort without modifying data if:

- zero trainers exist,
- more than one trainer exists and NULL client ownership is ambiguous,
- any existing client is already assigned to a different trainer unexpectedly.

Report the abort reason clearly.

## 2. Backfill existing clients

If exactly one trainer exists:

- take a pre-migration client count snapshot,
- assign only clients with trainer_id IS NULL to that trainer,
- use a transaction,
- verify that the total client count is unchanged,
- verify that zero clients have trainer_id IS NULL,
- do not delete or recreate clients, surveys, plans, notes, or sessions.

Do not apply NOT NULL until the old generic public survey creation flow has been replaced by the token-scoped flow below.

## 3. Application administrator

Add a fail-closed application admin allowlist:

`APP_ADMIN_CLERK_IDS`

Rules:

- IDs come only from environment configuration,
- an empty or missing allowlist grants no admin access,
- ordinary trainers see only records where trainer_id = their trainer id,
- an administrator may view all trainer-owned clients,
- being an owner/admin of the Replit workspace alone must not grant application admin access.

Do not expose complete Clerk IDs in logs or UI.

## 4. One-time survey invitations

Create a minimal `survey_invites` table containing:

- id
- trainerId
- tokenHash
- optional intendedEmail
- expiresAt
- usedAt
- revokedAt
- createdAt

Never store the raw token.

Add an authenticated trainer endpoint:

`POST /api/survey-invites`

It must:

- derive trainerId from the authenticated session,
- generate a cryptographically secure random token,
- store only its hash,
- return the raw invitation URL once,
- ignore trainerId supplied in the request body.

Add token-scoped public endpoints:

- `GET /api/public/survey/:token`
- `POST /api/public/survey/:token`

The POST endpoint must:

- reject invalid, expired, used, or revoked tokens,
- derive trainerId only from the matching invitation,
- create the client with that trainerId,
- save the submitted survey,
- mark the invitation as used,
- perform client creation, survey creation, and token consumption in one transaction,
- prevent duplicate submission from creating two clients.

The public survey endpoint must not expose:

- trainer notes,
- other clients,
- existing plans,
- trainer-only metadata.

## 5. Disable unsafe generic intake

Disable or replace every public route that can create a client without trainer ownership.

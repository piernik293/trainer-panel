TASK — Audit precise muscle assignment system

Review and test the recently implemented precise muscle assignment architecture in the Exercise Library.

IMPORTANT:

- Start with inspection and testing only.
- Do not redesign the application.
- Do not implement weekly volume calculations.
- Do not implement the workout plan editor.
- Do not commit or push.
- Do not make code changes before identifying and reporting the actual problems.
- If something is broken, describe the recommended fix and wait for approval.

==================================================
1. VERIFY EXISTING EXERCISE LIBRARY
==================================================

Confirm that:

- the Exercise Library loads correctly
- all existing exercises are still visible
- search and filters still work
- exercise details can be opened
- exercises can still be created and edited
- old exercises without specific-muscle assignments do not cause errors

Verify at least:

- Plank
- Podciąganie na drążku
- Przysiad ze sztangą
- Wyciskanie hantli nad głowę
- Wyciskanie sztangi leżąc

==================================================
2. VERIFY DATABASE ARCHITECTURE
==================================================

Inspect the database schema and confirm the existence and correctness of:

- specific_muscles
- exercise_muscle_assignments

Confirm that the assignment structure supports:

- exerciseId
- specificMuscleId
- one role: primary or secondary
- coefficient
- prevention of duplicate muscle assignments
- maximum one primary muscle per exercise
- foreign keys
- safe deletion behaviour

Confirm that exercises.mainMuscleGroup was preserved and still controls broad category filtering.

==================================================
3. VERIFY PULL-UP DATA
==================================================

Open and inspect:

Podciąganie na drążku

Expected broad category:

- Plecy

Expected assignments:

- Mięsień najszerszy grzbietu — primary — 1.0
- Mięsień dwugłowy ramienia — secondary — 0.5
- Mięsień obły większy — secondary — 0.5
- Mięsień czworoboczny grzbietu — secondary — 0.25

Report every difference from this expected structure.

==================================================
4. VERIFY BENCH PRESS DATA
==================================================

Open and inspect:

Wyciskanie sztangi leżąc

Expected broad category:

- Klatka piersiowa

Expected assignments:

- Mięsień piersiowy większy — primary — 1.0
- Mięsień trójgłowy ramienia — secondary — 0.5
- Przednia część mięśnia naramiennego — secondary — 0.5

The serratus anterior should not be assigned automatically.

Report every difference.

==================================================
5. VERIFY FORM BEHAVIOUR
==================================================

Inspect the create/edit exercise form.

Confirm that:

- exactly one primary specific muscle can be selected
- the primary coefficient is always 1.0
- the primary coefficient cannot be edited
- multiple secondary muscles can be added
- every secondary muscle has an editable coefficient
- the same muscle cannot be selected twice
- selected muscles can be removed
- appropriate muscles are filtered or grouped by broad category
- the interface remains understandable in Polish

Do not require old exercises to already have assignments.

A newly created exercise should require one primary muscle once the updated form is used.

==================================================
6. VALIDATION TESTS
==================================================

Test and confirm that the backend rejects:

1. The same muscle assigned twice.
2. Two primary muscles.
3. No primary muscle when assignments are submitted.
4. Primary coefficient different from 1.0.
5. Secondary coefficient below 0.
6. Secondary coefficient above 1.
7. Invalid muscle ID.
8. Invalid exercise ID.

Confirm that validation exists on the server, not only in the frontend.

Use safe test data or rollback temporary test changes.

Do not damage the existing exercise records.

==================================================
7. TRANSACTION TEST
==================================================

Verify that updating all muscle assignments is atomic.

Test a failed update containing:

- one valid assignment
- one invalid assignment

Expected result:

- the complete update is rejected
- no partial assignment is saved
- the previous valid data remains unchanged

==================================================
8. PERSISTENCE TEST
==================================================

Temporarily change one secondary coefficient on a safe test exercise.

Example:

- 0.5 to 0.6

Save it, refresh the page and reopen the exercise.

Confirm that the value remains saved.

Restore the original value afterward.

==================================================
9. CONFIRM CURRENT SCOPE
==================================================

Confirm that the current implementation does not yet calculate:

- weekly muscle volume
- effective sets
- total sets per muscle
- AI training recommendations

The current task should only contain the architecture and muscle assignments.

==================================================
10. TECHNICAL CHECKS
==================================================

Run:

- TypeScript type checking
- available automated tests
- database migration verification
- production build

Do not hide warnings or errors.

==================================================
11. REPORT
==================================================

Do not commit or push.

Return a structured report containing:

1. What works correctly.
2. What is missing.
3. What is implemented differently from the specification.
4. Database constraint results.
5. API validation results.
6. UI form results.
7. Transaction test result.
8. Type-check, test and build results.
9. Exact files that would need changes.
10. Recommended fixes in priority order.

Wait for approval before fixing anything.

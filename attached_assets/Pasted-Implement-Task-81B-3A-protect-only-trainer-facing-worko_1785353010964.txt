## Goal

An authenticated trainer may access workout sessions, execution logs, workout history, and progress data only for clients owned by that trainer.

Rules:

- unauthenticated trainer-facing request → 401,
- authenticated request for another trainer’s resource → 404,
- ownership comes only from the authenticated Clerk session,
- never trust trainerId from body, query params, headers, or URL,
- ownership must be checked before returning or modifying session data,
- client-facing portal routes remain unchanged.

## Ownership chains

For routes using clientId:

client → trainer

For routes using sessionId:

session → client → trainer

For routes using executionLogId:

execution log → session → client → trainer

For routes containing multiple IDs, require exact parent binding:

- session belongs to the supplied client,
- execution log belongs to the supplied session,
- session belongs to the trainer’s client.

A trainer owning Client A and Client C must not be able to access Client C’s session through Client A’s URL.

## Protection

Protect trainer-facing operations for:

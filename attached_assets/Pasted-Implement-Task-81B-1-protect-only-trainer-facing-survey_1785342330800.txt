## Goal

An authenticated trainer may access surveys, avoided exercises, and internal trainer notes only for clients they own.

Rules:

- unauthenticated private request → 401,
- authenticated request for another trainer’s client → 404,
- ownership must be derived through clients.trainer_id,
- never trust trainerId from request body, query params, headers, or URL,
- public token-based survey routes remain functional,
- internal trainer notes never appear in public responses.

## Survey routes

- reading a client survey,
- creating or updating a survey,
- partial survey updates,
- survey status,
- trainer-facing survey-derived endpoints,
- avoided exercises belonging to a client.

Every trainer-facing route containing clientId must verify ownership before reading or writing.

Do not create duplicate survey records for the same client.

## Trainer notes

- list notes,
- create note,
- update note,
- delete note.

For routes using noteId, derive ownership through:

note → client → trainer

Do not trust a separate clientId when ownership can be derived from the note.

## Query enforcement

- include trainer ownership in the database query,
- use an owner-scoped join or subquery,

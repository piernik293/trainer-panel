PHASE 2 — AUTOMATED MIGRATION

Implement and execute the smallest safe automated migration.

Requirements:

- run inside transactions,
- be idempotent,
- use stable identifiers or natural unique keys,
- insert missing records,
- update only catalogue records that correspond to the source,
- preserve all required relationships,
- avoid duplicate exercises,
- avoid duplicate relationship rows,
- never truncate tables,
- never delete production clients,
- never delete surveys,
- never delete saved plans,
- never overwrite unrelated production data.

Do not copy environment-specific numeric IDs blindly if those IDs may conflict.

Resolve relationships using stable keys such as:
- slug,
- canonical name,
- existing unique key,
- or another established repository identifier.

Do not invent exercises, muscles, equipment or generator attributes.

Use the current development/admin catalogue as the source of truth.

--------------------------------------------------
Data rules
--------------------------------------------------

Use only values already accepted by the existing importer.

Before writing each exercise:

- inspect existing canonical values,
- reuse existing Polish naming conventions,
- reuse existing muscle names exactly,
- reuse existing movementCategory values,
- reuse existing movementPattern values,
- reuse existing equipment values,
- reuse existing trainingLocation values.

Do not introduce unsupported values.

Use "Inny" only when no valid existing equipment category fits.

--------------------------------------------------
Exercise quality
--------------------------------------------------

Include commonly used, legitimate strength-training exercises across:

- barbells,
- dumbbells,
- cables,
- machines,
- bodyweight,
- Smith machine,
- resistance bands,
- kettlebells where supported.

Include beginner-friendly and advanced variations where appropriate.

Avoid:

- duplicate exercises,
- cosmetic naming differences,
- extremely niche variations,
- exercises with unclear or redundant purpose,
- multiple entries that differ only by grip unless the grip meaningfully changes the movement or target.

--------------------------------------------------
Metadata quality
--------------------------------------------------

Every exercise must:

- have exactly one primary muscle assignment,
- use valid secondary muscle assignments,
- use a valid movement pattern,
- use a valid movement category,
- use valid equipment values,
- use valid training locations,
- have isActive: true,
- have duplicateStrategy: "skip",
- pass completeness validation,
- be suitable for recommendation-pool use.

Keep compound exercises classified consistently with the existing library.

Keep isolation exercises classified consistently with the existing library.

--------------------------------------------------
Relations
--------------------------------------------------

Add substitutions, progressions and regressions only when the relation is clear and useful.

Do not create excessive or speculative relations.

All relation targets must either:

- already exist in the database,
- or exist within the same batch.

--------------------------------------------------
Validation workflow
--------------------------------------------------

For each batch:

1. Create the JSON file.
2. Run:
   POST /api/exercises/import/preview
3. If preview has any blocking error:
   - stop for that batch,
   - report the exact error,
   - do not import that batch.
4. If preview succeeds:
   - run POST /api/exercises/import
5. Verify:
   - exercises exist in the database,
   - muscle assignments exist,
   - exercises are returned by the library API,
   - exercises are available to the recommendation pool,
   - no duplicates were created.

Continue to the next batch only after the previous batch succeeds.

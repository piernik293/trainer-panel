# TASK — Stabilize Monorepo Builds, Generated Types and TypeScript Checks

IMPORTANT

This is a stabilization task only.

Preserve every existing feature exactly as it currently behaves.

Do NOT add new product features.
Do NOT redesign the UI.
Do NOT refactor unrelated code.
Do NOT modify business logic unless it is strictly required to resolve a verified type inconsistency.
Do NOT modify or delete existing database data.
Do NOT manually edit generated files when they can be regenerated from their source specification.

If any required change could alter runtime behaviour, stop and report it before applying that change.

The application currently works at runtime, but TypeScript checks fail because internal workspace package build outputs and generated API types are stale.

Known affected packages:

- @workspace/db
- @workspace/api-zod
- @workspace/api-client-react

Known additional type gap:

The API returns computed Exercise response fields:

- isComplete
- missingFields

but these fields are not currently represented in the official OpenAPI Exercise schema.

============================================================
OBJECTIVE
============================================================

Make the monorepo fully type-safe, reproducible and synchronized.

Expected final result:

- Internal workspace packages are rebuilt from the current source code
- Generated OpenAPI, Zod and React client types match the actual API
- isComplete and missingFields are included in the official Exercise response type
- API server TypeScript checks pass
- Trainer app TypeScript checks pass
- Existing runtime behaviour remains unchanged
- Existing database schema and data remain untouched
- Future builds do not rely on stale dist outputs

============================================================

The API currently returns these computed Exercise response fields:

- isComplete
- missingFields

Add them to the official OpenAPI Exercise response schema.

Required types:

- isComplete:
  - type: boolean

- missingFields:
  - type: array
  - items:
    - type: string

These fields are computed response fields.

They must NOT be added as database columns.

They must NOT be stored in the exercises table.

Do not duplicate or replace the existing completeness calculation.

The current dynamic completeness service must remain the single source of truth.

Verify that these fields are present in every generated Exercise response type used by:

- Exercise Library list
- Exercise detail

- Exercise update response
- Plan Editor exercise picker
- Recommendation endpoints, when they return Exercise objects

# GENERATOR STEP 4B3 — RECOMMEND EXERCISES FOR UNCOVERED VOLUME ONLY

Continue from the current repository state.

Step 4 already contains:

- manual exercise selection,
- exercise recommendations,
- live daily and weekly volume coverage,
- local selected-exercise state,
- separate Core coverage.

Implement only adaptive recommendation targeting based on the remaining planned
volume.

The recommendation engine must suggest exercises for targets that still need
volume instead of continuing to suggest exercises for targets that are already
covered or exceeded.

Do not modify:

- the existing exercise scoring formula,
- score values or score weights,
- volume-calculation formulas,
- muscle coefficients,
- exercise muscle assignments,
- Step 3 planned volume,
- daily distribution values,
- split logic,
- exercise prescription defaults,
- database schema,
- plan persistence,
- Step 5 preview,
- AI,
- supersets,
- drop sets.

Do not create a second recommendation engine.

============================================================
1. REUSE CURRENT SOURCES OF TRUTH
============================================================

Reuse the existing:

- generator volume coverage result,
- distributionResult,
- targetDecisions,
- daily targetAllocations,
- auxiliaryCoreBlock,
- Exercise Recommendation Engine,
- recommendation endpoint and service,
- selected exercises for the current workout day.

Do not calculate effective volume again.

Use the existing coverage result produced by the backend Volume Calculator.

Use the actual existing typed field names after inspecting the directly related
types.

Expected sources are currently:

Weekly planned volume:
distributionResult.targetDecisions[].weeklySelectedVolume

Daily planned volume:
distributionResult.days[].targetAllocations[].allocatedVolume

Weekly actual volume:
existing coverage result weekly target effectiveSets

Daily actual volume:
existing coverage result day muscle effectiveSets

Match normal volume targets by targetId.

Do not match only by visible muscle name.

============================================================
2. DETERMINE ELIGIBLE TARGETS
============================================================

For every normal target assigned to the selected workout day calculate only the
remaining need:

dailyRemaining =
plannedDailyVolume - actualDailyEffectiveVolume

weeklyRemaining =
plannedWeeklyVolume - actualWeeklyEffectiveVolume

Use tolerance:

0.01

A normal target is eligible for recommendations only when:

- plannedDailyVolume > 0,
- dailyRemaining > 0.01,
- weeklyRemaining > 0.01.

Exclude a target when:

- daily planned volume is already covered,
- daily planned volume is exceeded,
- weekly planned volume is already covered,
- weekly planned volume is exceeded,
- the target has no planned allocation in the selected day.

Do not mutate any planned or actual values.

============================================================
3. EXACT TARGET PRECISION
============================================================

Use targetId as the exact source of recommendation need.

Broad category may be used only to obtain the initial candidate set from the
existing recommendation engine.

It must not be the final eligibility check.

Example:

Broad category:
Plecy

Targets:
- Latissimus
- Trapezius

If Latissimus is covered but Trapezius remains uncovered:

- Trapezius remains eligible,
- Latissimus is excluded,
- recommendations must match an exercise assignment connected to the uncovered
  Trapezius targetId.

If Trapezius is covered but Latissimus remains uncovered, apply the inverse.

Do not mark the whole broad category as completed merely because one target in
that category is completed.

============================================================
4. MINIMAL EXISTING-ENDPOINT EXTENSION
============================================================

Prefer extending the existing read-only day-recommendations request with
optional exact target IDs rather than creating a new endpoint.

Allowed minimal request additions:

- uncoveredTargetIds
- includeCore, only when required

The existing recommendation service must still calculate all exercise scores.

Do not add a scoring formula to the route or React.

After existing scoring, keep a candidate only when its stored muscle
assignments contain at least one currently uncovered targetId with a valid
positive coefficient.

Return or expose the matching uncovered target IDs and labels needed by the UI.

If the current endpoint response already contains sufficient assignment data,
reuse it instead of extending the response.

Do not add database columns or migrations.

============================================================
5. CORE RECOMMENDATION NEED
============================================================

Core remains separate from the 11 analytical targets.

Use the same reliable Core classification already used by current coverage:

mainMuscleGroup === "Brzuch"

Do not use exercise-name matching.

Calculate Core recommendation eligibility from the existing direct-set coverage:

dailyCoreRemaining =
planned daily Core sets - actual daily direct Core sets

weeklyCoreRemaining =
planned weekly Core sets - actual weekly direct Core sets

Core is eligible only when both values are greater than zero.

When Core is covered or exceeded, do not automatically recommend more direct
Core exercises.

Do not count incidental trunk stabilization as direct Core.

============================================================
6. TARGET NEED ORDER
============================================================

Order eligible recommendation needs as follows:

1. planned target with zero actual contribution,
2. partially covered target with the highest remaining percentage,
3. original daily target-allocation order as the stable final tie-breaker.

For partial coverage:

remainingPercentage =
dailyRemaining / plannedDailyVolume

This ordering affects which target needs are handled first.

It must not alter individual exercise scores.

Within each target, preserve the existing Exercise Recommendation Engine
ranking.

============================================================
7. RECOMMENDATION RESULTS
============================================================

For each eligible target:

- use the existing scored candidate exercises,
- require a stored assignment to that exact uncovered targetId,
- select up to 3 matching recommendations.

For Core:

- require the existing direct Core classification.

Deduplicate the final result by exerciseId.

One exercise matching several uncovered targets must:

- appear once,
- show all currently uncovered targets it supports.

Keep the existing maximum:

8 unique recommendations per workout day.

Do not display an exercise already added to that workout day.

The same exercise may still be selected on another workout day.

============================================================
8. LIVE UPDATE BEHAVIOUR
============================================================

When the recommendation panel is open, update recommendation needs after the
existing volume coverage finishes recalculating following:

- adding an exercise from recommendations,
- adding an exercise manually,
- removing an exercise,
- replacing an exercise,
- changing working sets.

Do not refresh recommendation needs after changing:

- repetitions,
- RIR,
- rest time,
- notes,
- exercise order within the same day.

Do not send recommendation requests while volume coverage is still loading.

Use a short debounce.

Ignore stale recommendation responses.

An older response must never replace recommendations based on newer coverage.

Do not create repeated request loops between coverage and recommendations.

============================================================
9. COMPLETED DAY STATE

"Zaplanowana objętość tego dnia została pokryta."

"Możesz nadal dodać ćwiczenie ręcznie. Dodatkowa objętość zostanie oznaczona jako przekroczenie propozycji."

Keep the manual action:

"Dodaj ćwiczenie"

Do not block trainer control.

Do not automatically remove exercises or reduce sets.

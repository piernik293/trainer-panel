This is an architecture and specification task only.

==================================================
GOAL
==================================================

Create a deterministic rulebook that defines how every workout should be generated.

This rulebook will become the foundation used by future modules:

- DailyAllocationEngine
- SessionPlanningEngine
- ExerciseSelectionEngine
- SetAssignmentEngine
- ExerciseOrderingEngine
- ValidationEngine
- RepairEngine

The rulebook must describe WHAT the generator should do.

It must NOT describe HOW the code should implement it.

==================================================
INCLUDE RULES SUCH AS
==================================================

Training frequency

- Prefer approximately twice-weekly frequency for major muscle groups when feasible.

Weekly volume

- Weekly volume is more important than frequency.
- Frequency should help distribute weekly volume.

Fragmentation

- Avoid excessive fragmentation.
- Do not spread very small weekly allocations across many sessions without justification.

Movement patterns

Back should preferably include:

- vertical pull
- horizontal pull

Legs should preferably include:

- knee dominant movement
- hip dominant movement

Shoulders should preferably include:

- press
- lateral raise
- rear delt work

Exercise ordering

Default order:

1. Priority exercise
2. Primary compound
3. Secondary compound
4. Accessories
5. Isolation
6. Calves
7. Core

Priority exercise

If a client wants to improve a specific exercise
(for example Pull-up, Bench Press or Squat)

that exercise may start the workout.

Exercise duplication

Avoid selecting multiple exercises with nearly identical roles unless there is a specific reason.

Sets

Prefer ranges instead of fixed values.

Examples:

Primary compounds:
3–5 sets

Secondary compounds:
2–4 sets

Isolation:
2–4 sets

Core:
2–4 sets

Calves:
2–5 sets

Recovery

Avoid placing large workloads for the same muscle on consecutive sessions if better spacing exists.

Validation

The generator should validate:

- frequency
- movement pattern coverage
- weekly volume
- fragmentation
- ordering
- session feasibility
- priority implementation

==================================================
IMPORTANT
==================================================

The specification should distinguish between:

HARD RULES

Rules that should almost never be violated.

Examples:

- no duplicate exercise
- no impossible session

SOFT RULES

Rules that can be broken if required.

Examples:

- twice weekly frequency
- preferred ordering
- preferred set ranges

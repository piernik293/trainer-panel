## Task #84D — Verify and fix the real public survey request path

The previous task must not be considered complete.

CORS configuration has been improved, but the survey page still displays a network error. The local inspection showed that one request path is handled by the Vite SPA server and returns HTML instead of API JSON.

Do not assume that the external Replit proxy fixes this automatically.

### Objective

Prove that a newly generated survey invitation works through the actual public Replit URL, and fix the frontend/API routing if it does not.

### 1. Reproduce through the real public URL

Generate a fresh invitation and open its complete public HTTPS URL in an incognito browser.

Use browser Network tools or equivalent browser automation against the public `*.replit.dev` address.

Capture the invitation verification request:

- full request URL,
- request Origin,
- HTTP status,
- Content-Type,
- response body,
- Access-Control-Allow-Origin,
- which server handled the request.

The verification response must be JSON from the API server, not Vite `index.html`.

### 2. Verify the API URL construction

Inspect the survey frontend code and determine exactly how the verification endpoint URL is constructed.

Check:

- relative versus absolute URL,
- `VITE_API_URL`,
- path prefixes,
- Replit proxy and routing configuration,
- development versus deployed routing,
- whether `/client-landing/api/...` is incorrectly being generated,
- whether the correct endpoint is `/api/public/survey/...`.

Do not rely on assumptions about Replit path rewriting.

### 3. Fix routing if necessary

If the request reaches Vite instead of the API:

- correct the frontend API base URL,
- or add the correct explicit proxy/rewrite configuration,
- use the same established API-routing mechanism as working trainer-app requests.

Do not create a special insecure endpoint and do not bypass the API authentication or CORS middleware.

The public survey verification endpoint may be unauthenticated, but it must still be reached through the intended API route.

### 4. Validate response parsing

Before calling `response.json()`, verify the response Content-Type.

If the response is HTML or otherwise unexpected:

- treat it as a server/routing error,
- do not misclassify it as an invalid invitation,
- log enough development information to identify the request URL and response status,
- do not expose sensitive details in the production UI.

### 5. Review credentials behavior

The survey verification endpoint is public.

Confirm whether `credentials: "include"` is necessary for this specific request.

If it is not required, use a request configuration appropriate for a public token-verification endpoint while preserving restricted CORS.

Do not change authenticated client-portal requests that require Clerk session credentials.

### 6. Environment separation

Do not treat the temporary Replit development origin as the permanent production origin.

Clearly define and document:

- development trainer origin,
- development client/survey origin,
- production trainer origin,
- production client/survey origin.

Use the existing LOCAL_* variables for development where appropriate.

Do not allow arbitrary `*.replit.dev`.

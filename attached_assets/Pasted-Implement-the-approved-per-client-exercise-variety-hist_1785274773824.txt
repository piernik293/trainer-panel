==================================================

- id: serial primary key

- generation_id: PostgreSQL UUID, not null
- exercise_id: integer, not null, FK exercises(id), ON DELETE CASCADE
- generated_at: timestamptz, not null, default now()

UNIQUE (client_id, generation_id, exercise_id)

Indexes:

- client_id, generated_at DESC
- client_id, exercise_id

==================================================
6. STRICT IDEMPOTENCY
==================================================

Do not rely only on:

ON CONFLICT DO NOTHING

Required behaviour:

A. No rows currently exist for:

client_id + generation_id

→ insert the complete deduplicated exercise set.

B. Rows already exist and the stored exercise-ID set exactly equals the
incoming deduplicated set

→ return success without inserting duplicates.

C. Rows already exist but the stored exercise-ID set differs from the incoming
set

→ return HTTP 409 Conflict.

Do not merge two different payloads into one generation.

This guarantees that a network retry is safe, while accidental reuse of a
generationId for another plan is rejected.

The unique constraint remains the final database integrity guard.

==================================================
7. HISTORY READ FOR GENERATION
==================================================

Before calling ExerciseSelectionEngineV0 in generate-day, load per-client
automatic usage history.

Last four complete generations:

SELECT generation_id
FROM client_exercise_usage_log
WHERE client_id = :clientId
GROUP BY generation_id
ORDER BY MAX(generated_at) DESC
LIMIT 4;

Exercise usage aggregation:

SELECT
  exercise_id,
  COUNT(DISTINCT generation_id) AS total_generations,
  MAX(generated_at) AS last_used_at
FROM client_exercise_usage_log
WHERE client_id = :clientId
GROUP BY exercise_id;

Pass into the engine:

- total generation count per exercise
- last-used timestamp per exercise
- exercise IDs used in the previous four generations

History must always be scoped by client_id.

9. FALLBACK
==================================================

When every legal exercise for the required slot is inside the recent cooldown:

1. keep all mandatory filters,
2. choose the least recently used legal exercise,
3. when recency is equal, choose the least frequently used,
4. use the existing quality score as the next tie-breaker.

Record the internal reason:

“powtórzenie wymagane z powodu ograniczonej puli legalnych ćwiczeń”

four-generation cooldown.

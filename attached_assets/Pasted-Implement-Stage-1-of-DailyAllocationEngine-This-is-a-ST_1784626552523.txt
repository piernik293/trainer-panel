====================================================
GOAL
====================================================

Replace the current per-target daily volume distribution with a global allocation system that:

1. Allocates ALL muscle targets simultaneously across days
2. Prevents session overload
3. Preserves total weekly volume
4. Tracks unresolved volume explicitly
5. Returns feasibility status

====================================================
CURRENT PROBLEM
====================================================

The current system distributes each target independently:

chest → distribute
back → distribute
shoulders → distribute

This ignores that session capacity is shared.

This results in overloaded days (e.g. Legs = 38 effective volume).

====================================================
INPUT CONTRACT
====================================================

Create a new type:

DailyAllocationInput:

{
  days: Array<{
    dayIndex: number
    dayType: string   // e.g. "push", "pull", "legs", "upper", "lower", "full_body"
  }>

  weeklyTargets: Record<string, number>  // targetId → volume

  priorities?: Record<string, number>    // optional, not required in Stage 1

  constraints: {
    sessionMax: number   // hard max total per day
    sessionMin: number   // soft minimum per target per day
  }
}

====================================================
OUTPUT CONTRACT
====================================================

Create a new type:

DailyAllocationResult:

{
  days: Array<{
    dayIndex: number
    dayType: string

    allocations: Record<string, number>  // targetId → volume

    total: number
  }>

  weeklyAllocated: Record<string, number>

  weeklyUnresolved: Record<string, number>

  status: "feasible" | "feasible_with_tradeoffs" | "infeasible"
}

====================================================
ALLOCATION LOGIC (STAGE 1)
====================================================

1. Initialize empty allocation per day

2. For each target:
   - determine eligible days based on dayType
   - if no eligible days → add full volume to weeklyUnresolved

3. Distribute volume across eligible days BUT:

   - NEVER exceed sessionMax
   - Prefer even distribution
   - Respect sessionMin as a guideline, not hard rule
   - If remaining volume cannot fit → add to weeklyUnresolved

4. After all targets processed:

   - compute total per day
   - compute weeklyAllocated per target
   - compute weeklyUnresolved per target

====================================================
CONSTRAINTS
====================================================

HARD:

- No day total may exceed sessionMax
- No negative values
- All allocated + unresolved must equal original weeklyTargets

SOFT:

- Avoid splitting tiny values (e.g. 1–2 across multiple days)
- Prefer grouping volume

====================================================
FEASIBILITY STATUS
====================================================

Return:

"feasible"
→ if no unresolved volume AND no day close to max (safe margin)

"feasible_with_tradeoffs"
→ if unresolved > 0 OR days near max

"infeasible"
→ if large unresolved OR no valid distribution exists
